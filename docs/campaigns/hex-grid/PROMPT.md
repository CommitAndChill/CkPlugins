# Typed hex grids in CkGrid • executor brief

**Delivery contract.** A caller can create a finite flat- or pointy-topped board, pick and inspect a cell, reserve a rotated footprint, move it atomically, and recover the same placement IDs and exact cells after restore and late join. A square inventory may hold the same occupant. Its existing Blueprint pins, AngelScript calls, saved records and multiplayer behavior must continue to work.

**Acceptance rubric:** award one point per row below only when the phase's named tests, fixtures and observations are recorded in [PROGRESS.md](PROGRESS.md). Runtime release requires P1–P6 and P8 (7/7). Editor painting adds P7 (8/8). An unobserved behavior stays pending. These are executable specifications for future work. ## Architectural decisions

- Keep a typed sibling family in the existing runtime module. The board, cell, object, blocker and placement each have a typed handle and narrow Utils surface. The square 2dGridSystem exposes dimensions, rectangular coordinates, 90° rotations, slots and square-specific return types. Making it runtime-polymorphic would change contracts used by existing UHT assets and AS. A new plugin would add a dependency boundary without removing those contracts. Neither approach is needed to add a hex caller.
- Authoring assets contain immutable construction recipes. Params retain the layout/policy required for queries. Fragments own cell identity and mutable state. The board owns its index, validated projection and mutation order. Editor brushes, debug options, meshes and presentation live with their respective consumers. Introduce a runtime Tunables fragment only for an independently justified live policy.
- Store Q/R as signed integers. S, rotation intermediates and distance are widened. Cell order is (r,q). Geometric ties use (q,r) on the infinite lattice before domain membership. Stored cells are real generational handles inside one private registry per board. The public identity of a placement is (board, persistent GUID). Live placement handles are session-local.
- Compose and validate before publishing. A board mutation succeeds only after a complete commit. Forward projection, reverse links, cell reservations and terminal callbacks have one ordering. Each live occupant can have at most one placement across hex boards. Preserve an independent square membership. Keep rejected reservations and previous state intact.
- Rebuild layout from a reproducible, versioned authored recipe. Persist dynamic contributions and stable identities through one board-state handler. Independently resolvable objects own a separately registered binding GUID that survives restore and replication. Treat an incoming empty projection, an absent baseline, an intentionally anonymous placement, and a temporarily unresolved occupant as distinct states. Ordinary procedural construction is session-scoped. Client gameplay mutations use the project's authority routing.
- Design targets are finite disks and explicit sets with holes, a six-direction topology, arbitrary rigid pivot orientation and finite positive uniform scale. A proposed 65,536-cell admission ceiling is a defensive allocation bound, subject to a lower validated registry capacity. It is **not a promised game workload**. The Technical Director chooses supported board counts, sizes and frame/memory budgets after P8 measurements. Inventory migration, cross-board transfer, whole-grid snapping/precise overlap, EQS hex queries, pathfinding, streaming and a new renderer each require separate product scope.

## Caller and ownership map

Paths in this table are relative to the host checkout. The phase briefs carry native signature shapes, destinations and line anchors. Proposed APIs and tests do not exist at the planning baseline.

| Caller or boundary | Executor action |
|---|---|
| CkCore / CkEcs | Reuse current math frames, handles, private world, lifetime, requests, Record and persistence registrar. No axial value moves into CkCore. Any necessary neutral restore/correlation extension is a bounded prerequisite with its own review and compatibility proof. |
| CkGrid/2dGridSystem and CkInventory/Inventory/Spatial | Preserve square reflected types, type IDs, save keys, AS generated namespaces and inventory admission/transfer. Inspect old consumers in the final compatibility gate. New callers opt into HexGrid Utils and axial pins explicitly. |
| Debugger EQS overlay, Cartesian grid helpers and game scripts | Retain existing square sampling and 2D/3D meanings. No automatic conversion from FIntPoint, FIntVector, lengths or world rounding. Route a later hex EQS item through P1/P2 on its own scope. |
| New native EntityScripts, authored board/object assets and runtime spawners | Single resolved Spec through the same typed factory. Expose valid input/output pins and explicit failure paths. Use runtime spawn transforms and actual pivot composition. |
| Blueprint and AngelScript consumers | Generate new reflected functions/mixins and types from native declarations. Run real call graphs with constructed handles and completion signals. Old square assets and generated wrappers retain names and pin types. |
| CkTests | Production-style C++, AS, Blueprint and authored fixtures, extended gym, mixed replicated subject and snapshot/travel tests. Generated net stubs may require a second build before fresh discovery. |
| CkGameplayDebugger/Source/CkGridEditor | Existing single component visualizer dispatches on typed authoring. Hex editor mode is independently selectable. Runtime depends on neither paint mode nor meshes. |
| Snapshot and network consumers | Keep legacy square payload registration and existing mixed-world callers. P5 introduces one save-only registrar per type (board state and object identity). P6 upgrades both registrations in place to split apply. The board carries the object's binding key across both transports. |

## Operating rules

Work in this checkout. Read the host and Foundation AGENTS guides plus the canonical skills referenced in each phase. Before execution compare the three plugin HEADs and local changes against [the recorded design baseline](PROGRESS.md). Refresh relevant origin/dev refs under the host's in-place and editor-lock rules, then examine drift before using line anchors. Preserve local work. The package is an implementation specification and grants no publishing authority.

For an expected runtime failure return the typed result in all builds. For developer invariants keep the total check and its entire recovery inside CK_ENSURE_IF_NOT. Do not publish any partial state. Any source contradiction affecting identity, readiness, public schemas, transaction order or dependency direction belongs with the lead before dependent work. P5a recommends that CkEcs expose per-entity, per-payload, per-load-epoch restore disposition before the board or occupant publishes readiness. CkSnapshot owns classification. Approve this bounded framework change before P5 implementation. A new neutral capability needs its own focused review and gate. Record missing evidence and keep its phase open.

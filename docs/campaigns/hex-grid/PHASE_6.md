## Implementation and decision branches

1. Resolve all bounded seams, then add tests first. Fixture follows existing bridged subject construction: root is net-correlated, owns a square board and hex feature without adding two conflicting feature instances to the same entity; if square/hex require distinct root entities, use properly correlated production driver-created child for one, not two independent `Request_CreateEntity` copies. Store test handles transient/local-only; reacquire owner after travel. Give mapped occupant real snapshot reconstruction identity and a separately proved net correlation token. Do not mistake identical labels in independently spawned worlds for the same entity.
2. Add a baseline container entry on authority when the replicated hex feature is composed, including the empty projection. Use `TryAddContainerFragment<FCk_RepData_HexGridState>` and shared Produce. Correlatable objects also publish their identity payload via their own real entity drivers. A server-only occupant reserves its cells indefinitely on the client, with the binding key unresolved until the authority removes it or object correlation succeeds. Its absence cannot trigger a local death-watch or baseline timeout. Add this case and duplicate unresolved key rejection to LateBindingAndConflicts. One authority replicate processor publishes committed projection with `TryProduce`/`TryUpdateContainerFragment`; arm it on placement/rules/blockers/restore changes, and on initial construction. Local/session-only boards do not require a replication container. Unsupported persistent procedural board stays session-only unless P5 recipe contract is fulfilled.
3. NetApply checks structural presence before writes, returning NotReady only for absent composition. Validate schema/recipe/full projection and all valid occupant uniqueness BEFORE mutation. Commit synchronously and return Applied only after P4 transaction success; do not enqueue unchecked work for a ClientOnly processor and then claim success. Last-applied cache now describes accepted state. Preserve old accepted state on Rejected, even when the final entry is bad. Replay is ID keyed; changing anchor/rotation for an existing ID replaces exact cells; removal diffs by ID; never use Occupant as key. Suppress authority gameplay success callbacks on the client, while exposing explicitly documented projection/readiness notifications after consistent state is committed.
4. Initial successful complete apply, including empty, records accepted-baseline generation and releases AwaitingReplication once coherent; invalid/rejected first baseline becomes Unavailable with explicit failure. Retained older accepted state can remain usable after a later rejected update, with failure notification, because rejection did not replace that baseline. NetRemove atomically clears the accepted projection and transitions replicated feature to Unavailable (Destroyed/removal reason); it is not a valid empty snapshot. Public removal of a placement is an empty/fewer-entry state update, not removal of the whole replicated feature.
5. Prefer existing replication-complete edge for terminal inspection: if the board expects baseline but no accepted baseline exists when the driver declares initial completion, report explicit missing/rejected cause; do not interpret completion as success. For a connection that never delivers a baseline or completion, use a hex-owned initial baseline deadline measured by `FPlatformTime::Seconds`, armed only for actual replicated-client expectation. Deadline must exceed `ck::PendingApplyTimeoutSeconds` plus a dispatch frame so a received-but-NotReady payload has its framework outcome first. The proposed initial-baseline deadline is `PendingApplyTimeoutSeconds + 5.0` seconds; this bounds elapsed waiting, not proof the dispatcher rejected. If an actual existing completion reports terminal failure sooner, use that cause. Timeout transitions Unavailable/ReplicationTimedOut and reports the terminal failure. Requests arriving while waiting already returned NotReady. A later valid baseline for the current live epoch can recover only via a new atomic apply and notified transition. A superseded epoch or destroyed board cannot be reopened. Do not alter global retry limits, refresh deadline on repeated bad packets, or restart after destruction. Test via injected monotonic clock seam where practical, plus one actual delayed-dispatch fixture.
6. Reconcile delayed occupant association only through the reviewed stable token. Reservation state may be committed while identity unresolved, so board readiness does not wait for occupant validity. On association, revalidate current ID/generation, live object type, pending destruction and global hex backref before one atomic association transaction. If already bound elsewhere, preserve both existing claims/reservations and emit one conflict result. An accepted occupant's later death uses normal P4 removal policy on authority, then replication clears clients. Tests distinguish unresolved reference from deliberate anonymous and ensure rejected/replaced tokens cannot bind stale records.
